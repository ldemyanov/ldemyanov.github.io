# Возможные технические улучшения

Список основан на текущем коде репозитория. Это предложения для следующих задач, а не утверждения о найденных сбоях в опубликованном сайте.

## Высокий приоритет

1. **Ограничить память интерактивного Canvas.** **src/components/home/InteractiveBackdrop.astro** создаёт холст высотой во всю страницу с плотностью до 2×. На длинной странице это может занимать много памяти. Измерить потребление на мобильных устройствах и при необходимости разбить холст на области или ограничить число физических пикселей, сохранив рисунок при прокрутке.

## Средний приоритет

2. **Синхронизировать размеры изображений в данных.** В **src/data/highlights.ts** атрибуты width/height для некоторых изображений отличаются от размеров файлов. Часть карточек задаёт геометрию CSS, поэтому видимого сбоя может не быть, но точные значения уменьшат риск скачков при загрузке. Проверить размеры всех изображений и отдельно сохранить нужное кадрирование через CSS.
3. **Упростить отображение периода проекта.** В **src/pages/work/[...slug].astro** есть отдельная проверка имени проекта **sbercraft** для даты. Даты уже хранятся в frontmatter, поэтому эту ветку можно убрать после проверки всех записей и сделать единую схему отображения.
4. **Автоматизировать проверку frontmatter и сборки в pull request.** Сейчас workflow запускается на push в **main** и вручную. Отдельная проверка на pull request с **npm ci**, **npm run check** и **npm run build** обнаружит ошибки схем и типов до публикации; задача deploy должна по-прежнему выполняться только из **main**.
5. **Проверить формат служебных изображений для платформ.** Фотографии и скриншоты приведены к WebP. PNG-иконки приложения и Open Graph обложка сохранены для совместимости. При будущем обновлении дизайна проверить, какие форматы поддерживают нужные платформы, и хранить только действительно необходимые варианты.

## Низкий приоритет

6. **Вынести повторяющиеся значения адреса сайта в одно место.** Адрес задан в **astro.config.mjs** и повторяется в **src/config/site.ts** как запасное значение. Общая функция или доступ к **Astro.site** уменьшат вероятность расхождения canonical URL и JSON-LD при смене домена.
7. **Документировать жизненный цикл блога перед включением.** Коллекция и компоненты для статей сохранены, но маршруты не создаются. Перед включением подготовить правила черновиков, навигацию по статьям и Open Graph данные; текущие заметки находятся в **spec/mock-content-cleanup-plan.md**.

## Выполнено

- **Метаданные npm согласованы с репозиторием.** Имя пакета, описание, ключевые слова и ссылки обновлены в **package.json**; имя синхронизировано с **package-lock.json**.
- **Проверка локальных ссылок после сборки.** Скрипт **scripts/check-local-links.mjs** проверяет цели в **dist/** и останавливает **npm run build** при ошибках; GitHub Actions использует эту же команду.
