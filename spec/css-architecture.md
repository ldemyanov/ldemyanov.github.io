# Структура CSS и адаптивный дизайн

## Точка входа и порядок

`src/layouts/BaseLayout.astro` подключает `src/styles/global.css`. Этот файл импортирует стили в следующем порядке:

| Файл | Назначение |
| --- | --- |
| `fonts.css` | Локальные `@font-face` для Unbounded и IBM Plex Sans |
| `tokens.css` | Все глобальные CSS-переменные в `:root` |
| `base.css` | Сброс, базовая типографика, контейнер `.swp-shell`, отступы `.wrap` и `.sec`, шкала заголовков |
| `components.css` | Общие кнопки, чипы, иконки, заголовки секций и эффекты появления |
| `sections.css` | Шапка, секции главной страницы и футер |
| `pages.css` | Внутренние страницы: кейсы, услуги, контакты, статьи и формы |

`src/components/home/InteractiveBackdrop.astro` содержит локальные стили своего интерактивного фона. Остальные общие и страничные правила находятся в файлах выше. Порядок импортов влияет на каскад: более позднее правило с той же специфичностью перекрывает раннее.

## Переменные

Единое место для глобальных CSS-переменных — `src/styles/tokens.css`. Здесь заданы палитра (`--swp-*`), шрифты (`--font-display`, `--font-body`), ширина страницы и горизонтальный отступ (`--shell`, `--pad`), радиусы (`--r-*`), вертикальный ритм секций (`--sec`, `--sec-tight`) и кривая анимации (`--ease`). При изменении общей темы или повторяющегося размера сначала проверяйте этот файл. Новые глобальные переменные добавляйте туда; локальное значение, нужное только одному компоненту, оставляйте рядом с его правилами.

`.swp-shell` ограничивает страницу шириной `--shell` и центрирует её. `.wrap` задаёт отступы от краёв через `--pad`; `.sec` и `.sec-tight` используют переменные вертикальных отступов. Это общая основа для секций и внутренних страниц. Не задавайте каждой секции собственную ширину страницы без необходимости.

## Резиновая вёрстка

- Для значений, которые должны плавно меняться с шириной окна, используйте `clamp(минимум, гибкое значение, максимум)`. Так уже заданы `--pad`, `--sec`, заголовки `.d1`–`.d4`, некоторые `gap` и внутренние отступы карточек. Минимум и максимум защищают от слишком тесной мобильной и чрезмерно растянутой десктопной версии.
- Для сеток используйте `minmax(0, 1fr)` или доли с `minmax(0, …fr)`, когда длинный текст может распереть колонку. Для повторяющихся карточек, когда их количество должно зависеть от доступного места, подходит `repeat(auto-fit, minmax(…px, 1fr))`.
- Для текста ограничивайте длину строки через `max-width` в `ch`, как у `.prose` и `.hero-copy`. Не растягивайте абзацы на всю ширину большого экрана.
- Изображения должны оставаться внутри контейнера. Общий `img { max-width: 100%; }` находится в `base.css`; форму обложки задавайте через `aspect-ratio`, а кадрирование через `object-fit` и `object-position`. Если оригинал нельзя увеличивать, используйте `max-width: 100%` и естественные размеры изображения вместо `width: 100%; height: 100%`.
- Для узких экранов проверяйте, что длинные заголовки, адреса и названия технологий переносятся. В сетках допускайте сжатие содержимого через `min-width: 0`; при необходимости применяйте `overflow-wrap: anywhere` к тексту.

## Адаптивные переходы

Плавное изменение размера через `clamp()` используйте, пока композиция остаётся той же. Медиазапрос добавляйте тогда, когда должна измениться сама структура: число колонок, порядок элементов, вид навигации или положение боковой панели. Ставьте медиазапрос рядом с правилами соответствующего блока и выбирайте ширину по моменту, когда содержимое перестаёт помещаться, а не по названию устройства.

Существующие структурные переходы:

| Блок | Где | Текущий переход |
| --- | --- | --- |
| Навигация | `sections.css` | При `1000px` и уже горизонтальное меню заменяется мобильным |
| Первый экран | `sections.css` | При `1080px` три колонки становятся двумя; при `720px` — одной. Отдельные отступы `.hero-grid` действуют от `1081px` |
| Блоки главной | `sections.css` | Сетки перестраиваются примерно на `880px`, `700px`, `560px` и `420px` по потребности каждого блока |
| Услуги на главной | `sections.css` | От `1200px` пять карточек стоят в одной строке; ниже работает `auto-fit` |
| Кейсы и контакты | `pages.css` | При `900px` кейс теряет боковую колонку; при `880px` контакты и поля формы становятся одноколоночными |

Это пороги конкретных блоков, а не единая шкала для всего сайта. Не меняйте их глобально ради одного элемента. Если переход выглядит резким, сначала настройте гибкие размеры и перенос текста, затем при необходимости меняйте структуру на подходящей ширине.

## Как вносить изменения

1. Найдите существующий селектор в нужном слое. Для общих компонентов правьте `components.css`, для секций главной — `sections.css`, для внутренних страниц — `pages.css`.
2. Проверьте, не задаётся ли нужный цвет, шрифт или общий отступ в `tokens.css`. Не дублируйте глобальную переменную локальным числом без причины.
3. Сначала настройте плавное поведение между ширинами; медиазапрос добавьте только для перестройки композиции. Держите правило и его адаптивные варианты в одном разделе файла.
4. Учитывайте состояния `:hover`, `:focus-visible`, открытое мобильное меню и `prefers-reduced-motion`. Для главной страницы есть правила с `body.home-page`; они не должны случайно менять внутренние страницы.
5. Просматривайте результат на узком телефоне, планшете, обычном и широком десктопе, а также между точками перехода. Особенно проверяйте горизонтальный скролл, перенос текста, высоту изображений и порядок элементов.
