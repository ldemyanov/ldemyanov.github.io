# Запись Performance-трассы интерактивного фона

Скрипт **scripts/trace-interactive-backdrop.mjs** управляет отдельным Brave через Chrome DevTools Protocol. Он прогревает canvas, записывает 300 движений мыши за примерно 5 секунд и сохраняет полную трассу в игнорируемой Git папке **reports/**. Для запуска нужен Node.js версии из **package.json** и установленный Brave или другой браузер на базе Chromium.

## Один прогон

Из корня проекта запустите одну команду:

```bash
npm run profile:backdrop:before
```

Команды `profile:backdrop:before` и `profile:backdrop:after` собирают текущую версию сайта, запускают Astro preview на `127.0.0.1:4322`, дожидаются загрузки страницы и шрифтов, записывают отчёт и завершают запущенный preview. Изображения с `loading="lazy"` вне экрана специально не ожидаются. Отдельно открывать `npm run preview` не нужно. Скрипт не вызывает Git и сохраняет файлы только в **reports/**. Brave из `/Applications/Brave Browser.app` находится автоматически. Если он установлен в другом месте, передайте путь через `--chrome "/путь/к/Brave Browser"` или переменную `CHROME_PATH`. Необязательные `--width`, `--height` и `--dpr` меняют размер окна и плотность экрана; по умолчанию это 1440 × 900 CSS-пикселей при DPR 1. Метаданные содержат фактический размер буфера canvas после прогрева.

Скрипт создаёт пару файлов **reports/backdrop-before-…json.gz** и **reports/backdrop-before-…meta.json**. Откройте `.json.gz` в Brave DevTools → Performance через загрузку профиля. Метки **backdrop-benchmark-start** и **backdrop-benchmark-end** ограничивают измеряемый интервал. В `.meta.json` находятся фактическая длительность, максимальное опоздание отправки событий, версия браузера и параметры окна.

## Сравнение двух версий

Для версии «до» запустите `npm run profile:backdrop:before`, для версии «после» — `npm run profile:backdrop:after`. Каждая команда собирает ту версию кода, которая находится в текущей рабочей копии. Если в старой версии этих команд ещё нет, соберите и запустите её отдельно, а скрипт записи вызовите из рабочей копии с новым кодом: `npm run profile:backdrop -- --url http://127.0.0.1:4321/ --label before`. Удобно держать версии в отдельных Git worktree.

Сделайте по три прогона каждой версии при одинаковом размере окна, версии Brave и прочих условиях. Сравнивайте медианы времени обработки `pointermove`, числа `TimerInstall` и работы кадров между метками. При существенном различии фактической длительности или максимального опоздания повторите прогон. Прогрев перед началом трассы исключает создание большого canvas из замера обработки событий указателя.

Для оценки изменения разрешения canvas на Retina-экране используйте `--dpr 2` в обоих вариантах. Предыдущие отчёты с DPR 1 для этого сравнения не подходят. В `meta.json` проверьте `viewport.devicePixelRatio`, `canvas.browserDpr`, `canvas.bufferWidth` и `canvas.cssWidth`: при прежней реализации отношение `bufferWidth/cssWidth` равно 2, при буфере DPR 1 — равно 1. Замер начинает запись **после** прогрева и выделения буфера, поэтому время первого выделения памяти и максимальный объём памяти по одной трассе не оцениваются. Дополнительно сравните чёткость тонких линий глазами на реальном экране с высоким DPR.

### Проверка буфера DPR 1

На устройстве с высоким DPR откройте главную при масштабе браузера 100%, подвигайте мышью и выполните в DevTools Console:

```js
const canvas = document.querySelector('#interactive-backdrop');
({ browserDpr: window.devicePixelRatio, canvasScale: canvas.width / parseFloat(canvas.style.width) });
```

После изменения `canvasScale` должен быть равен 1 даже при `browserDpr` 2. Сравните чёткость следов на той же странице и при том же масштабе с предыдущей версией.

Для численного сравнения держите предыдущую версию сайта в отдельном worktree и запустите её preview на `127.0.0.1:4322`. Из рабочей копии с актуальным скриптом трижды вызовите `npm run profile:backdrop -- --url http://127.0.0.1:4322/ --label dpr2-before --dpr 2`. Затем остановите старый preview и трижды вызовите `npm run profile:backdrop:after -- --dpr 2` на новой версии. Сравнивайте только отчёты с одинаковыми `viewport.devicePixelRatio`, размером viewport и числом событий. Метаданные покажут сокращение размеров буфера, но сам CDP-прогон не измеряет объём памяти canvas напрямую.
