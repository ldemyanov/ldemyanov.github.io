# Запись Performance-трассы интерактивного фона

Скрипт **scripts/trace-interactive-backdrop.mjs** управляет отдельным Brave через Chrome DevTools Protocol. Он прогревает canvas, записывает 300 движений мыши за примерно 5 секунд и сохраняет полную трассу в игнорируемой Git папке **reports/**. Для запуска нужен Node.js версии из **package.json** и установленный Brave или другой браузер на базе Chromium.

## Один прогон

В первой вкладке терминала запустите собранную версию сайта:

```bash
npm run build
npm run preview -- --host 127.0.0.1 --port 4321
```

Во второй вкладке запустите запись:

```bash
npm run profile:backdrop:before
```

Команды `profile:backdrop:before` и `profile:backdrop:after` сами задают имена отчётов. Скрипт не вызывает Git и только сохраняет файлы в **reports/**. Brave из `/Applications/Brave Browser.app` находится автоматически. Если он установлен в другом месте, передайте путь через `--chrome "/путь/к/Brave Browser"` или переменную `CHROME_PATH`. Необязательные `--width` и `--height` меняют размер окна; по умолчанию это 1440 × 900 CSS-пикселей при DPR 1.

Скрипт создаёт пару файлов **reports/backdrop-before-…json.gz** и **reports/backdrop-before-…meta.json**. Откройте `.json.gz` в Brave DevTools → Performance через загрузку профиля. Метки **backdrop-benchmark-start** и **backdrop-benchmark-end** ограничивают измеряемый интервал. В `.meta.json` находятся фактическая длительность, максимальное опоздание отправки событий, версия браузера и параметры окна.

## Сравнение двух версий

Соберите и запустите каждую версию сайта по очереди на одном адресе. Для версии «до» запустите `npm run profile:backdrop:before`, для версии «после» — `npm run profile:backdrop:after`. Скрипт записи запускайте из рабочей копии, где он уже есть: старой версии сайта не требуется содержать этот скрипт. Удобно держать версии в отдельных Git worktree, чтобы не переключать файлы работающего сервера.

Сделайте по три прогона каждой версии при одинаковом размере окна, версии Brave и прочих условиях. Сравнивайте медианы времени обработки `pointermove`, числа `TimerInstall` и работы кадров между метками. При существенном различии фактической длительности или максимального опоздания повторите прогон. Прогрев перед началом трассы исключает создание большого canvas из замера обработки событий указателя.
